Every command is reached through `$`, generated by `mcjs2 gen` from your version's command tree
(`commands.json`). Words of a command are properties, arguments are calls:

```ts
import { $ } from "#mc";

$.tp("@a", "0 ~10 0");                            // tp @a 0 ~10 0
$.give("@s", "diamond", 3);                       // give @s diamond 3
$.scoreboard.players.add("@s", "kills", 1);       // scoreboard players add @s kills 1
$.effect.give("@a", "speed", 10, 1, true);        // effect give @a speed 10 1 true
$.tellraw("@a", { text: "Hi", color: "gold" });   // tellraw @a {"text":"Hi","color":"gold"}
$.title("@a").title({ text: "Fight!" });          // title @a title {"text":"Fight!"}
```

Your editor follows the tree: after `$.` it lists the commands, after `$.scoreboard.` the
subcommands, and each call shows the argument names and types Minecraft uses.

## Properties

Literal words are written as in Minecraft, in snake_case: `$.scoreboard`, `$.ban_ip` (`ban-ip`),
`$.team.modify("red").collision_rule` (`collisionRule`). Gamerules are the same across versions:
`keepInventory` and `minecraft:keep_inventory` are both `$.gamerule.keep_inventory`.

JavaScript keywords work as property names, so they stay as they are: `$.function(Helper)`,
`$.execute.if.entity("@p")`, `$.execute.in("the_nether")`, `$.return(1)`. The only exceptions are
names JavaScript itself gives a meaning to: a `then` literal would be `then_` (otherwise every chain
would look like a promise), and likewise `constructor_` and `proto_`. None of these exist in
Minecraft today.

Words that aren't identifiers keep their exact spelling and use brackets:

```ts
$.execute.if.score("@s", "kills")[">="]("@s", "best").run.say("record!");
```

## Calls

A call takes one or more arguments in order. These are the same:

```ts
$.tp("@a", "~ ~1 ~", "90 0");
$.tp("@a")("~ ~1 ~")("90 0");
```

When two syntaxes start with arguments of the same kind, like `tp <targets> <location>` and
`tp <destination>`, both stay possible until the next value decides. A value no syntax accepts is a
build error that points at your source line:

```
[mcjs2] No syntax of "tp" matches arguments ("@a", "0 1").
    at src/main.ts:3:30
```

Commands that end with a word, or have nothing left to pass, are complete without a call:

```ts
$.swing("@s").mainhand;   // swing @s mainhand
$.reload;                 // reload  ($.reload() works too)
```

## Complete commands

Each `$.` starts a new line. When the function ends, every line must be a complete command:

```ts
$.execute.as("@a");
// Incomplete command "execute as @a" in Main (main.ts:3). Continue it, e.g. with .run.say(...).
//     at src/main.ts:4:3
```

A chain can be stored and continued more than once. Each continuation is its own line:

```ts
const atPlayers = $.execute.as("@a").at("@s");
atPlayers.run.say("one");   // execute as @a at @s run say one
atPlayers.run.say("two");   // execute as @a at @s run say two
```

## Raw commands

Calling `$` itself writes a line as-is. Use it for macro lines or anything the library doesn't cover:

```ts
$("say written as-is");
$("$tp @s $(x) $(y) $(z)");              // macro line
$`schedule function ${Tick} 1s`;          // template: functions become their ids
$(Helper);                                // function pk:main/helper
```

See [raw content](/guides/raw-content/#raw-commands).

## Typed ids

Arguments that take registry ids (blocks, items, entity types, effects, ...) autocomplete the ids
from your version's `registries.json`, with or without the `minecraft:` prefix. Tags
(`#minecraft:logs`) are accepted where the game accepts them. Any other string is accepted too, for
ids your data pack or a mod defines.

## Positions

Positions are strings, written the same as in game:

```ts
$.tp("@s", "~ ~1 ~");                     // relative
$.tp("@s", "0 64 0");                     // absolute
$.tp("@s", "^ ^ ^5");                     // local (relative to rotation)
$.fill("~-1 ~ ~-1", "~1 ~ ~1", "glass");
```

The types reject positions Minecraft would reject: the wrong number of coordinates, or mixing
local (`^`) with world coordinates. The build checks again, for strings built at runtime.

## High-permission commands

Commands that need a higher permission level than functions have (`op`, `stop`, `ban`, ...) are
still there, with a note in their JSDoc, because they can't run from a data pack.

## Version differences

`$` is generated per version, so commands and arguments that don't exist in your version aren't
there. Where an argument kept its name but changed format between versions (text components,
scoreboard slot names, ...), the types and the serialization follow your version. See
[versions](/reference/versions/).
